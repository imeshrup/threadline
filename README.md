# Threadline: MERN clothing store

A complete e-commerce site for a clothing brand: React (Vite) storefront, Node/Express REST API, MongoDB, and Stripe Checkout.

## Features

**Storefront**
- Home page with hero, categories, featured and new products
- Shop page: search, filters (category, gender, size, color, price, on sale), sorting and pagination, all kept in the URL
- Product page: color/size variants with per-variant stock, image per color, quantity, wishlist, related products
- Reviews with star ratings, rating breakdown and a "verified buyer" badge for customers who bought the item
- Slide-out cart drawer and cart page (saved in the browser), with a free-shipping progress bar
- Checkout: shipping address (can be saved to the account), standard or express delivery, tax, and payment
- Order page with a status tracker, pay-now for unpaid orders, and cancellation (stock goes back on the shelf)
- Accounts: register/login (JWT), profile and password, saved address, order history, wishlist

**Admin** (`/admin`)
- Dashboard: revenue, 30-day revenue chart, order counts, average order value, top sellers, low-stock alerts
- Products: create/edit/delete, colors, sizes, a stock grid per color × size, image upload or URL, sale price, featured flag
- Orders: filter by status, mark shipped (with tracking number) and delivered, cancel and restock
- Customers: order count and lifetime spend, grant/revoke admin, delete

**Backend safeguards**
- Prices and totals are always worked out on the server; prices sent by the browser are ignored
- Stock is reserved atomically when an order is placed, so two shoppers can't buy the last item; it's released on cancel
- Payment marking can't be applied twice (pending → paid only), whether it comes from the webhook or the success page
- bcrypt password hashing, rate-limited auth, helmet, and upload type/size limits

## Quick start

Requirements: Node 18+ and MongoDB (local install, Docker, or a free MongoDB Atlas cluster).

```bash
npm run install:all
cp server/.env.example server/.env    # then edit values
docker compose up -d                  # starts MongoDB on :27017 (skip if you have one)
npm run seed                          # 25 products, demo users, 40 sample orders
npm run dev                           # API on :5000, site on http://localhost:5173
```

## Payments (Stripe)

With `STRIPE_SECRET_KEY` blank, checkout runs in **demo mode** and payment is simulated, so the whole flow works with no account.

To take real (test-mode) payments:
1. Put your `sk_test_...` key in `server/.env` as `STRIPE_SECRET_KEY`.
2. Checkout now redirects to Stripe. Pay with card `4242 4242 4242 4242`, any future date and any CVC.
3. When the shopper comes back, the order page confirms payment with Stripe. For production, also add a webhook:
   ```bash
   stripe listen --forward-to localhost:5000/api/payments/webhook
   ```
   Put the `whsec_...` secret it prints into `STRIPE_WEBHOOK_SECRET`. Subscribe to `checkout.session.completed`.

## Tests

```bash
npm test
```

API integration tests (auth, catalog filters, ordering, stock reservation, payment, reviews, admin) run against an in-memory MongoDB via `mongodb-memory-server`, which downloads a MongoDB binary the first time.

## Production

```bash
npm run build      # builds client/dist
npm start          # Express serves the API and the built site on PORT
```

Set `NODE_ENV=production`, a strong `JWT_SECRET`, `MONGO_URI`, and `CLIENT_URL` (your public URL, used for Stripe redirects). Uploaded images are saved in `server/uploads/`; on hosts with temporary disks, use persistent storage or swap in S3/Cloudinary in `server/src/routes/upload.js`.

## Project layout

```
server/src
  models/        User, Product (variants, reviews), Order
  routes/        auth, products, orders, users, admin, upload, webhook, garment (SVG images)
  middleware/    auth (JWT, admin), error handling
  utils/         pricing, stock reservation, stripe, slugify
  data/          catalog + seed script
client/src
  context/       Auth, Cart, Wishlist, Toast
  components/    Header, Footer, CartDrawer, ProductCard, UI kit
  pages/         Home, Shop, Product, Cart, Checkout, Order, Auth, Account
  pages/admin/   Dashboard, Products, ProductEdit, Orders, Users
```

Product images in the seed data are simple SVG illustrations generated by the API (`/img/garment/:type/:hex.svg`), so the store works with no image hosting. Replace them with real photos in the admin product editor.
